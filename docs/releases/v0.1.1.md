# ReefProof v0.1.1

ReefProof v0.1.1 is a recommended hotfix for everyone running the published
v0.1.0 OCI image. It restores the browser Workbench that was unintentionally
shipped without its JavaScript bundle.

## What changed

- Restored Workbench sign-in, navigation, status, Evidence, sessions, database
  inspection, system map, and manual return-flow policy interactions in the
  published container.
- Made the sign-in form fail safely with `POST` when JavaScript is unavailable,
  preventing credentials from falling back into the browser URL.
- Added release checks that fail when the Workbench bundle is absent and an OCI
  smoke test that starts the packaged service and fetches the real asset.

## Who should upgrade

Upgrade if you deployed ReefProof v0.1.0 from GHCR. The characteristic symptom
is a Workbench page that loads visually but does not respond, with
`/assets/workbench.js` returning `404`.

There is no database schema change in this hotfix. Preserve the existing
`/var/lib/reefproof` data mount when replacing the image.

## Upgrade image

Deploy the immutable Linux amd64 image:

```text
ghcr.io/bobbravo2/reefproof@sha256:6a46991ea9cdad6655e1a29d92ffc8c5a1b2674888e209f49d9da3c09ddbe511
```

Tags are for discovery; use the digest above for deployment.

## Changelog

- Fixed the release staging contract so the generated Workbench bundle is a
  tracked, required artifact.
- Fixed the no-JavaScript authentication fallback to avoid query-string
  credential submission.
- Added packaged-container acceptance coverage for the Workbench bundle.
- Updated ReefProof's package, CLI, desktop, and OCI identity to `0.1.1`.

[Compare v0.1.0...v0.1.1](https://github.com/bobbravo2/ReefProof/compare/v0.1.0...v0.1.1)

## Safety boundary

ReefProof remains offline configuration assurance. HYDROS remains runtime
authority: this release does not connect to HYDROS, publish MQTT messages,
control equipment, or perform automatic remediation.
