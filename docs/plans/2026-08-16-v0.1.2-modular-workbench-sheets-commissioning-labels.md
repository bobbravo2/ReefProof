# ReefProof v0.1.2 — Modular Workbench, Live Sheets Commissioning, and Bulk Labels

Status: Accepted product/architecture plan for v0.1.2 implementation.

Date: 2026-08-16

## Outcome

Refactor the Workbench into small page-owned frontend modules **and** land one complete production data spine for the real Primary Reef System:

`Google Sheets -> ReefProof authored import -> human acceptance -> canonical system state -> observed/authored reconciliation -> commissioning -> deterministic label CSV`

The frontend refactor is not successful if it only modularizes the current Mock Collective and return-flow workflows. The v0.1.2 architecture must prove that the new seams support the real commissioning workflow without adding a SPA, duplicating Google Sheets, weakening the HYDROS read-only boundary, or moving domain authority into the browser.

The release target is one shippable vertical slice that can read the live system workbook, preserve source provenance, create and accept authored candidates, represent actual device/port/cable identity, calculate commissioning posture, and export Brother P-touch-compatible bulk label CSV.

## Product decisions

These decisions are explicit and should not be re-opened by implementation agents unless a contradictory repository invariant is discovered.

1. **Use Google Sheets live.** ReefProof reads the configured Google Sheet through a server-side, read-only Google Sheets adapter. XLSX/CSV export is not the primary v0.1.2 path.
2. **Do not recreate Sheets in ReefProof.** Google Sheets remains the rich tabular authoring interface for design intent. ReefProof presents source status, diffs, acceptance, reconciliation, commissioning, evidence, and generated outputs rather than generic spreadsheet editing.
3. **Trust flows one way from Sheets into ReefProof.** Sheet data is authored source evidence. Importing it never silently mutates canonical ReefProof state. Accepted import facts become durable ReefProof state and remain available when the Sheet is offline or stale.
4. **Grounded/proven ReefProof state never regresses because Sheets is stale.** A later Sheet sync may propose changed authored intent or expose a contradiction, but it may not erase accepted commissioning evidence, fault-test evidence, label verification, observed HYDROS evidence, or historical accepted facts.
5. **Initial imported tabs are exactly:** `BOM`, `DOMAINS`, `POWER`, `DEVICE_INTERFACES`, `OUTPUTS`, and `MODES`.
6. **Stable source IDs remain source IDs.** `BOM_ID`, `DOMAIN_ID`, `DEVICE_ID`, output IDs, mode IDs, and other stable external identifiers are retained verbatim as namespaced external identities. ReefProof owns canonical namespace-qualified identities.
7. **ReefProof owns commissioning truth.** Commissioning is evidence-backed system state, not a lifecycle field copied blindly from Sheets.
8. **ReefProof owns the label CSV seam.** Brother P-touch remains the renderer/printer. ReefProof does not own printer drivers or direct printer control in v0.1.2.
9. **Canonical initial label vocabulary:** `DEVICE`, `PORT`, `CABLE`, `POWER SUPPLY`.
10. **Every removable connection is labeled at both physical ends.** Endpoint completeness is a commissioning invariant.

## Safety and authority boundary

HYDROS remains runtime authority. v0.1.2 adds no live HYDROS transport, browser-side HYDROS access, MQTT publication, equipment control, controller mutation, or automatic remediation.

Google Sheets is a **read-only authored-source transport** from ReefProof's perspective. ReefProof does not write back to the workbook in v0.1.2.

The browser never parses Google Sheet rows, never stores Google credentials, never constructs canonical domain state, and never decides whether imported data is trusted. All source parsing, normalization, validation, identity resolution, candidate generation, acceptance, commissioning evaluation, and label generation occur in backend-owned typed modules.

## Source-of-truth model

ReefProof must make the following distinction explicit in code, persistence, APIs, and UI:

### Google Sheets — authored design source

Authoritative for the latest fetched **authored intent** represented by the six in-scope tabs:

- product/BOM association;
- named power domains and source descriptions;
- planned device interfaces;
- planned outputs;
- authored modes;
- authored power/circuit relationships present in the workbook.

A successful fetch produces immutable source evidence plus a normalized import candidate set. Sheet content is never directly canonical ReefProof truth.

### ReefProof — durable accepted and proven system state

Authoritative for:

- canonical physical instance identity;
- accepted authored revisions;
- observed HYDROS evidence;
- source-to-canonical identity bindings;
- actual physical connections;
- commissioning checks and evidence;
- power/comms verification;
- fault-injection evidence;
- failure-mode dispositions;
- labels generated/applied/verified;
- contradictions, unknowns, trust events, and historical audit state.

### HYDROS — runtime authority

Authoritative for what the controller currently does when represented by explicit observed evidence. Observed HYDROS state does not overwrite authored intent, and authored intent does not masquerade as observed state.

## Live Google Sheets integration

### Backend adapter

Add a narrow provider interface such as:

```python
class AuthoredSystemSource(Protocol):
    def fetch(self) -> AuthoredSourceSnapshot: ...
```

The production v0.1.2 implementation is `GoogleSheetsSource`. Tests use deterministic fake providers; domain code must not import Google SDK types.

The adapter is read-only and server-side. Credential acquisition/storage is isolated behind a credential-provider interface so local-managed and remote-hosted packaging can evolve without contaminating parsing or domain contracts.

Do not put a Google client in page controllers or endpoint adapters.

### Fetch boundary

For each synchronization, fetch exactly the six named tabs. Preserve enough source metadata to support deterministic replay and operator drill-down:

- spreadsheet ID;
- spreadsheet title;
- configured source alias;
- source fetch timestamp;
- provider modification/version metadata when available;
- each tab name;
- bounded source ranges used;
- normalized selected-cell content hash;
- whole in-scope source snapshot hash;
- row number/A1 provenance for every imported record;
- parse warnings and validation diagnostics.

Do not persist Google access tokens, refresh tokens, cookies, or other credentials as evidence.

### Offline behavior

A source-fetch failure must not invalidate already accepted ReefProof state.

Expose source health independently:

- `CURRENT` — latest successful fetch is within configured freshness policy;
- `STALE` — accepted state remains usable but the source has not been refreshed within policy;
- `UNAVAILABLE` — live fetch failed; last accepted/imported source remains available;
- `CHANGED` — live source differs from the latest accepted authored import and requires review.

A stale or unavailable Sheet is not equivalent to unknown device commissioning state. The UI must explain the difference.

## Identity architecture

### Canonical ReefProof identity

Use ReefProof-owned namespace-qualified canonical IDs that are independent of any single source system.

Recommended grammar:

```text
rp:<project-id>:<kind>:<stable-slug>
```

Examples:

```text
rp:primary-reef-system:device:hydros-x10-01
rp:primary-reef-system:device:xp8-main6
rp:primary-reef-system:power-domain:main6-120v-20a
rp:primary-reef-system:port:xp8-main6-output-6
rp:primary-reef-system:cable:cbl-0001
rp:primary-reef-system:power-supply:kraken-psu-01
```

The grammar is a ReefProof namespace, **not a vendored Google/HYDROS identity**. Slugs are human-readable handles but canonical identity must not be regenerated automatically from a renamed Sheet label after creation.

### External identity binding

Represent external identity separately, for example:

```text
source_system = google_sheets
source_instance = <spreadsheet-id>
namespace = BOM_ID
value = BOM-000047
```

or:

```text
source_system = hydros
source_instance = <snapshot/source identity>
namespace = device_reference
value = <vendor reference>
```

A canonical object may have multiple external IDs from multiple sources. External IDs are unique within `(source_system, source_instance, namespace)` and remain queryable forever.

This allows future humans and agents to add new authored sources, manufacturer serials, alternate controllers, or migration tooling without changing canonical IDs.

### Instance rule

Never create multiple physical devices merely because a BOM row has `QTY_REQUIRED > 1`.

`BOM_ID` identifies a procurement/catalog line. A physical ReefProof device instance requires an explicit instance identity such as a `DEVICE_ID`, accepted physical discovery/mapping, or another future typed instance source.

## Sheet normalization contract

Implement six narrow tab adapters. Do not build a generic spreadsheet ORM or formula evaluator.

### BOM

Import only fields required by system identity, commissioning requirements, reliability, or reconciliation. Preserve `BOM_ID` as external identity.

Useful initial fields include item/model name, category, reliability tier, authored circuit/power-domain reference, dependencies/provides, criticality, failure impact, location, and serial/lot when present.

Procurement price, vendor shopping workflow, budget formulas, and unrelated historical/chemistry content remain outside canonical ReefProof state unless a later feature explicitly needs them.

Sheet lifecycle fields may be preserved as **authored claims** but may not directly set `commissioned=True`.

### DOMAINS

Import named power/failure domains and explicit source/protection attributes. Duplicate IDs fail closed.

### POWER

Import source/circuit/domain relationships represented explicitly by the workbook. Hyperlinks are provenance metadata, not domain authority.

### DEVICE_INTERFACES

Import explicit device instances and planned interfaces. Duplicate header names are a schema error unless an accepted schema mapping disambiguates them.

The current workbook has repeated `POWER_DOMAIN_ID` headers; v0.1.2 must treat this as an actionable import diagnostic rather than silently selecting one.

### OUTPUTS

Import explicit output identities and device/controller/port relationships. Formula errors such as `#REF!` are diagnostics and may not become accepted facts.

### MODES

Import explicit authored mode identities, membership, allowed/excluded behavior, and only semantics represented by the source schema. Unknown controller semantics remain UNKNOWN.

## Import pipeline

The live source pipeline is:

```text
Google Sheets
    |
    v
raw source snapshot metadata + selected cells
    |
    v
six strict tab adapters
    |
    v
normalized authored records
    |
    v
schema + referential validation
    |
    v
identity resolution / proposed bindings
    |
    v
import diff
    |
    v
candidate facts grouped by object and import batch
    |
    v
human acceptance authority
    |
    v
append-only canonical ProjectState
```

### Import batch

Persist an immutable `AuthoredImportBatch` with:

- import batch ID;
- source snapshot ID/hash;
- source freshness metadata;
- parser/schema version;
- normalized content hash;
- record counts by tab/type;
- diagnostics;
- proposed candidate IDs;
- acceptance status.

Re-fetching byte/content-equivalent in-scope data must be idempotent and produce no new canonical facts.

### Diff states

Backend projection must group changes as:

- `NEW`;
- `CHANGED`;
- `UNCHANGED`;
- `CONFLICT`;
- `INVALID`;
- `REMOVED_FROM_SOURCE`.

`REMOVED_FROM_SOURCE` never deletes canonical history. It creates an explicit proposed retirement/removal or conflict requiring human review.

### Acceptance UX

Do not present hundreds of imported scalar facts as the current one-card-per-candidate Sessions UX.

Create an import-review projection grouped by source object and semantic change. Allow explicit human acceptance/rejection at a useful batch/object level while preserving the underlying immutable candidate/decision/event chain.

Bulk acceptance must never bypass per-candidate deterministic validation.

## Connection model

Physical connections are ReefProof-grounded state even when planned endpoints originate in Sheets.

Represent every removable connection with:

- canonical cable/connection ID;
- connection class: `power`, `control`, `sensor`, or `data` initially;
- canonical `from_port_id`;
- canonical `to_port_id`;
- zone for each endpoint;
- device for each endpoint;
- port display name for each endpoint;
- applicable power domain/circuit when relevant;
- provenance and accepted/verified timestamps;
- label manifest linkage;
- physical label verification for both ends.

Use **FROM / TO consistently** across power, control, sensor, and data connections. Do not switch vocabulary to source/destination, upstream/downstream, controller/device, A/B, or male/female in the generic connection model.

Directional semantics can be attached separately when required by a protocol.

## Commissioning model

A device is not commissioned because it is marked Installed in the workbook or because it appears in HYDROS.

A device reaches `COMMISSIONED` only when every applicable requirement is proven.

### Core commissioning requirements

1. **Inventory identity proven**
   - canonical device exists;
   - source identity bindings are accepted;
   - physical location/zone is accepted.

2. **Failure modes dispositioned**
   - every registered applicable failure mode has an explicit disposition;
   - allowed dispositions initially include accepted risk, alerted/detected, or automated mitigation;
   - no applicable failure mode remains silently unconsidered.

3. **Electrical connections inventoried**
   - every applicable power input/output is represented;
   - power-domain/circuit mapping is known or explicitly UNKNOWN with a blocking commissioning gap;
   - power-supply objects are separately identifiable where applicable.

4. **All removable connections mutually traceable**
   - each cable has exactly two accepted endpoints for the initial model;
   - both endpoints resolve to canonical ports;
   - FROM and TO agree on one shared canonical cable identity.

5. **Labels physically complete**
   - required DEVICE / PORT / CABLE / POWER SUPPLY labels have been generated as applicable;
   - each removable cable is labeled at both physical ends;
   - operator verification records that the printed labels were applied to the intended endpoints.

6. **Power verified**
   - power behavior is verified with timestamped evidence;
   - deviations that matter to the device's failure model have a disposition.

7. **Communications verified when applicable**
   - control/data communications are tested for networked or controller-attached equipment;
   - non-applicable devices carry an explicit N/A reason rather than silently passing.

8. **Fault injection complete**
   - every controllable surface has a registered fault-test requirement;
   - failure is deliberately injected or otherwise deterministically simulated/tested within the safe test boundary;
   - expected detection, alert, safe behavior, or mitigation is recorded;
   - a missing fault test is UNKNOWN, never PASS.

9. **Environmental/leak failure coverage where applicable**
   - water-bearing or leak-risk equipment has explicit leak-detection/mitigation coverage or an accepted-risk disposition.

10. **No unresolved blocking contradiction**
    - accepted authored intent and observed evidence may disagree, but a blocking contradiction prevents COMMISSIONED until reconciled or explicitly accepted under policy.

### Commissioning states

Use explicit states rather than a single boolean:

- `NOT_STARTED`;
- `IN_PROGRESS`;
- `BLOCKED`;
- `COMMISSIONED`;
- `REVOKED` or equivalent trust-invalidated posture when underlying trusted evidence is revoked.

The derived state is backend-authored from requirement results. Missing evidence is `UNKNOWN` at the requirement level and may not be rendered as green/success.

### Fault-test model

Introduce typed `ControlSurface` and `FaultTest`/`Verification` records instead of one free-form commissioning note.

Examples include power removal, control-link loss, sensor unavailable, flow loss, pump/controller disconnect, expected fallback/safe state, alarm delivery, and leak detection where appropriate.

Do not require unsafe destructive tests. A failure mode may be satisfied by an accepted deterministic simulation or bounded safe test only when the policy explicitly permits that evidence type.

## Label model and CSV seam

### Canonical label kinds

Initial vocabulary is exactly:

- `DEVICE`
- `PORT`
- `CABLE`
- `POWER SUPPLY`

Use these terms in API enums, UI copy, fixtures, CSV records, and contributor documentation.

### Cable label content

For **every removable connection**, print a label at both physical ends with the same mutually traceable route identity:

```text
FROM: <zone · device · port>
TO: <zone · device · port>
CABLE: <stable cable display ID>
```

The `CABLE:` value must never be blank in generated production output. It is a short stable human-facing identifier linked to the full canonical ReefProof cable ID.

Both physical ends receive labels containing the complete FROM/TO route. The local endpoint may be indicated by template formatting later, but the text contract remains FROM / TO / CABLE.

### Deterministic label manifest

Generate a backend-owned `LabelManifest` from accepted canonical state.

Recommended record fields:

```text
manifest_id
manifest_schema_version
label_policy_version
project_id
label_id
label_kind
canonical_subject_id
display_id
from_zone
from_device
from_port
to_zone
to_device
to_port
primary_text
secondary_text
copies
sort_group
source_project_sequence
source_import_batch_ids
generated_at
```

For cables, `copies=2` by default because both ends must be labeled.

The same canonical project sequence plus the same label-policy version must generate byte-for-byte equivalent logical CSV content apart from an explicitly excluded generation timestamp field. Prefer omitting volatile timestamps from the CSV itself if they would break reproducibility.

### CSV boundary

Add a backend endpoint and CLI command that export CSV suitable for P-touch Editor database/bulk-print workflows.

The CSV is a **derived artifact**, never an authoring source and never canonical state.

ReefProof does not directly discover/control the Brother printer in v0.1.2.

### Physical label verification

CSV generation proves only that labels can be printed. It does not prove that they are physically present.

Provide a bounded commissioning action to mark each label/endpoint as applied and verified, recording operator, timestamp, manifest/label identity, and evidence/rationale as appropriate.

### Endpoint-completeness invariant

Add a deterministic invariant equivalent to:

> No removable connection is commissioned until both physical ends are labeled and mutually traceable to the same accepted canonical cable and endpoint pair.

Required outcomes:

- PASS only when both ends are verified;
- UNKNOWN when either endpoint, label, or verification evidence is missing;
- FAIL/BLOCKED when endpoints contradict each other or a verified label references the wrong canonical connection.

## Deterministic invariants required in v0.1.2

At minimum implement and expose:

1. **Source schema integrity** — required tabs/headers/IDs are unambiguous and valid.
2. **External identity uniqueness** — one external ID cannot silently bind to multiple canonical subjects.
3. **Referential integrity** — imported device/domain/output references resolve or remain explicit UNKNOWN/INVALID.
4. **No silent canonical overwrite** — changed Sheet data creates candidates/conflicts rather than direct mutation.
5. **Connection endpoint completeness** — every commissioned removable cable has exactly one accepted FROM and TO endpoint.
6. **Cable dual-label completeness** — both physical ends are label-verified and mutually traceable.
7. **Electrical inventory completeness** — applicable device power connections and domains are represented.
8. **Failure-mode disposition completeness** — no applicable registered failure mode is undispositioned for a commissioned device.
9. **Power/comms verification** — applicable checks have accepted evidence.
10. **Fault-test completeness** — every applicable controllable surface has accepted bounded fault-test evidence.
11. **Commissioned-device aggregate** — `COMMISSIONED` only if every applicable commissioning requirement passes and no blocking conflict remains.

Missing evidence produces UNKNOWN/BLOCKED posture; optimistic defaults are forbidden.

- source adapters produce typed normalized source records, not canonical state;
- canonical identity is ReefProof-owned;
- external identity is always namespaced;
- candidates require deterministic validators;
- only explicit authority decisions create canonical facts;
- commissioning is derived from evidence, never copied from a Sheet status cell;
- labels derive from canonical accepted connections;
- no frontend module reads provider-specific raw data;
- no generic abstraction without at least two immediate in-scope uses;
- no silent inference where UNKNOWN is appropriate.

## Compatibility

Preserve:

- existing `/workbench*` URLs;
- existing `/v1/workbench/*` and `/v1/projects/*` contracts unless an additive versioned extension is required;
- authentication/session semantics;
- `/assets/workbench.js` deployment path;
- Electron as shell around the same served Workbench;
- SQLite backup/replay behavior;
- generated OpenAPI TypeScript contracts;
- HYDROS runtime authority and no-control boundary.

New source/import/commissioning/label endpoints are additive.

## Explicit non-goals

- editing Google Sheet cells from ReefProof;
- generic spreadsheet UI;
- spreadsheet formula engine;
- bidirectional Sheet sync;
- automatic acceptance of changed Sheet data;
- direct Brother printer control;
- WYSIWYG label designer;
- QR/RFID asset system unless separately planned;
- live HYDROS polling/control;
- MQTT equipment behavior;
- automatic remediation;
- generic graph database;
- generic plugin framework;
- chemistry/livestock/budget import in v0.1.2.

## Final release acceptance

v0.1.2 is not accepted until a clean candidate proves all of the following:

- frontend is page-owned and browser-tested;
- one current configured Google Sheet is read live through the backend adapter;
- exactly the six in-scope tabs are normalized through strict schemas;
- duplicate/ambiguous headers and broken references fail closed;
- source provenance survives into accepted evidence;
- stable external IDs map to ReefProof-owned canonical IDs;
- Sheet changes create reviewable diffs/candidates, never silent canonical mutation;
- accepted ReefProof state remains usable during Sheet outage/staleness;
- observed HYDROS evidence remains epistemically separate;
- one real/synthetic device can complete the full commissioning state machine;
- every applicable failure mode is dispositioned;
- power and communications are verified where applicable;
- every controllable surface has accepted bounded fault-test evidence;
- one removable cable has accepted FROM/TO endpoints, two generated labels, two physical label verifications, and mutual traceability;
- deterministic label CSV exports DEVICE / PORT / CABLE / POWER SUPPLY records;
- no removable cable/device reaches COMMISSIONED while endpoint/label evidence is incomplete;
- `make test/frontend`, full Python suite, registered evaluations, uninterrupted `make check`, generated-artifact parity, packaged Electron smoke, and loopback browser acceptance all pass;
- release artifacts contain no Google credentials, private Sheet cell dumps beyond approved persisted authored evidence, raw HYDROS secrets, or browser credentials.

## Stop conditions

Stop and require an explicit architecture decision if implementation would:

- need ReefProof to write to Sheets;
- need the browser to hold Google credentials;
- infer physical device instances from BOM quantity alone;
- make a Sheet lifecycle cell directly authoritative for commissioning;
- overwrite accepted/proven ReefProof state during source synchronization;
- erase historical state when a source row disappears;
- silently choose between duplicate headers or ambiguous external IDs;
- generate a cable label without two canonical endpoints and a non-empty stable cable ID;
- mark a removable connection commissioned before both labels are physically verified;
- mark a device commissioned with undispositioned failure modes, missing applicable power/comms evidence, or incomplete controllable-surface fault tests;
- introduce a live HYDROS/control path;
- require a generic spreadsheet/domain/plugin framework to satisfy this release.

## One implementation detail intentionally kept replaceable

Google credential mechanics are an infrastructure concern behind the source adapter, not part of the authored-system domain contract. v0.1.2 must use a server-side read-only credential provider and must keep credentials out of evidence/SQLite exports/browser state. The implementation may choose the least-complex deployment-compatible credential method for the current Primary Reef System, provided the provider boundary remains replaceable and the full packaged/hosted acceptance gates are preserved.
