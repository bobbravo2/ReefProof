# v0.1 LXC deployment validation

Use this procedure only with the exact clean v0.1 candidate commit. It validates
offline ReefProof artifacts and a private-LAN Proxmox LXC deployment. It does
not authorize live HYDROS access, MQTT publication, equipment control, public
ingress, or automatic remediation.

## 1. Pin and identify the candidate

```bash
git status --short
git rev-parse HEAD
git show -s --format='%H%n%cI%n%s' HEAD
sed -n 's/^version = "\([^"]*\)"/\1/p' pyproject.toml
```

Stop unless status is empty and the version is `0.1.0`. Record the full commit
as `CANDIDATE_REVISION`. Do not build from uncommitted changes.

## 2. Run source and REPL acceptance

```bash
.codex/skills/reefproof-local-ci/scripts/run.sh local-check
./reefproof
```

In the attached console, verify the visible `reefproof>` command palette,
keyboard navigation, and return routes. Choose **Desktop Workbench**, then
verify it offers both **Local managed** and **Remote hosted**. Selecting remote
without an origin must fail with a concrete private-LXC command and must not
start a local daemon.

## 3. Build and verify every local artifact

```bash
.codex/skills/reefproof-local-ci/scripts/run.sh local-bundle
make build/desktop-app
python scripts/build-verify.py --root dist
git status --short
```

The build must finish from the exact clean commit. The final status may contain
only ignored build output; tracked or non-ignored changes invalidate the
candidate. Record:

```bash
./dist/reefproof version
shasum -a 256 dist/reefproof dist/*.tar.gz dist/reefproof.spdx.json \
  dist/build-manifest.json dist/reefproof-image.json
jq '{product,source,runtime,artifacts}' dist/build-manifest.json
```

Confirm the version and revision equal the candidate. Confirm the manifest,
SPDX SBOM, checksums, standalone archive, and OCI receipt are present. Never
publish `dist/` merely because these local checks pass.

## 4. Inspect and exercise the macOS app artifact

```bash
APP_ARCH=$(node -p 'process.arch')
APP="dist/desktop/ReefProof-darwin-${APP_ARCH}/ReefProof.app"
test -d "$APP"
node scripts/verify-desktop-package.mjs
find "$APP/Contents/Resources" -type f | sort
```

Stop if Resources contains `.local`, authenticator state, SQLite files, WAL/SHM files,
logs, snapshots, private exports, or browser evidence.

Run local-managed mode:

```bash
REEFPROOF_DESKTOP_MODE=local-managed open "$APP"
```

Verify the title shows `local-managed` and `http://127.0.0.1:8787`; authenticate,
run diagnostics, create a backup, restart the owned runtime, quit, and confirm
no owned daemon remains. Confirm application data is under the macOS ReefProof
application-data directory, never inside the `.app`.

After the hosted service is ready, run remote-hosted mode from a terminal so
the app receives the explicit configuration:

```bash
REEFPROOF_DESKTOP_MODE=remote-hosted \
REEFPROOF_REMOTE_ORIGIN=http://PRIVATE_LXC_IP:8787 \
  "$APP/Contents/MacOS/ReefProof"
```

Verify the title shows the exact origin and `HTTP LAN`. Authenticate, run hosted
diagnostics, download a hosted backup to a new local destination, verify it with
`sqlite3 BACKUP.sqlite3 'PRAGMA integrity_check;'`, and request restart. Confirm
the app waits for a new hosted uptime and never creates or starts local ReefProof
data, PID, log, database, or daemon state.

## 5. Transfer the exact OCI image to the private LXC

The local build tag is `reefproof:build-${CANDIDATE_REVISION:0:12}`. Prefer an
immutable registry digest when available. For an offline transfer:

```bash
podman save "reefproof:build-${CANDIDATE_REVISION:0:12}" \
  --output "/private/tmp/reefproof-${CANDIDATE_REVISION}.oci.tar"
shasum -a 256 "/private/tmp/reefproof-${CANDIDATE_REVISION}.oci.tar"
```

Copy that archive through the operator-approved Proxmox/LXC path, verify the
hash inside the LXC, then:

```bash
podman load --input "/path/reefproof-${CANDIDATE_REVISION}.oci.tar"
podman image inspect "reefproof:build-${CANDIDATE_REVISION:0:12}" \
  --format '{{json .Labels}}'
```

The image revision and version labels must match the candidate. If using LXD or
Incus tooling rather than Proxmox commands, perform these Podman steps inside
the selected container instance; do not expose a Docker/Podman socket to
ReefProof.

## 6. Start the hosted service with narrow authority

Inside the private LXC, create the durable volume and a Podman secret without
placing the operator token on the command line or in the repository:

```bash
podman volume create reefproof-data
read -r -s REEFPROOF_ACCEPTANCE_SECRET
printf '%s' "$REEFPROOF_ACCEPTANCE_SECRET" | \
  podman secret create reefproof-operator-token -
unset REEFPROOF_ACCEPTANCE_SECRET
```

Start the exact image. Replace only the uppercase placeholders:

```bash
podman run --detach --name reefproof-workbench \
  --restart=always \
  --read-only --cap-drop=all \
  --tmpfs /tmp:rw,noexec,nosuid,nodev \
  --volume reefproof-data:/var/lib/reefproof \
  --publish PRIVATE_LXC_IP:8787:8787 \
  --secret reefproof-operator-token,type=env,target=REEFPROOF_BOOTSTRAP_SECRET \
  --env REEFPROOF_HOSTED_RESTART_MODE=supervised-self-terminate \
  "reefproof:build-${CANDIDATE_REVISION:0:12}" \
  serve --bind 0.0.0.0 --port 8787 --no-open
```

Confirm the LXC firewall allows only the intended private LAN and that there is
no public/NAT ingress. Do not grant privileged mode, host PID namespace, a
container socket, additional capabilities, or a general host-management API.

## 7. Validate hosted behavior and persistence

From the LXC and then from the desktop host:

```bash
curl --fail http://PRIVATE_LXC_IP:8787/v1/system/health/live
curl --fail http://PRIVATE_LXC_IP:8787/v1/system/status | jq .
podman logs reefproof-workbench
```

Use the remote desktop for the authenticated checks. Record the operation audit
evidence after diagnostics, backup creation, one-time download, and restart.
The downloaded backup must pass `PRAGMA integrity_check`; replaying its opaque
download URL must return `404`.

After remote restart, record the new container start time and confirm the same
SQLite evidence remains. Then restart the LXC through the normal Proxmox/LXD
operator workflow, not through ReefProof. Repeat health, authentication,
diagnostics, storage integrity, and evidence checks.

## 8. Record the release evidence honestly

Capture the candidate revision, artifact hashes, OCI image ID/digest, LXC ID and
private address, commands, timestamps, results, and downloaded-backup hash.
Report each boundary as `VERIFIED`, `NOT TESTED`, or `UNKNOWN`. Local success is
not target-LXC proof. Do not call v0.1 ready while packaged dual-mode acceptance,
target-LXC service restart, LXC restart persistence, or any required release
evidence remains unverified.
